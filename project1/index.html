Objective

This project looks at two pretrained models without training or fine-tuning either one. Part 1 opens up a Vision Transformer (ViT): how an image becomes a sequence of patch tokens, and what a classifier with a fixed set of 1000 ImageNet labels can and cannot answer. Part 2 uses CLIP, which compares images with free-text descriptions: I implement its similarity computation, test how prompt wording affects zero-shot classification, and explore which images CLIP considers similar.

Both parts use the same collection of 20 images, so the two models can be compared directly. The focus is on understanding the computations and analyzing the results.

Part 1: Understanding a Pretrained Vision Transformer

Task 1: Image patches and model inputs.

ViT-B/16 does not look at an image as a grid of pixels. It splits the image into non-overlapping 16 x 16 patches and processes them as a sequence of tokens, like words in a sentence. I wrote my own split_into_patches() function, which reshapes a (C, H, W) tensor into (N, C, 16, 16) in row-major order, the same order the model uses.

Number of Patches and Sequence Length

N = (H / P) x (W / P) = (224 / 16) x (224 / 16) = 14 x 14 = 196 patches
sequence length = 196 patches + 1 CLS token = 197 tokens, each of dimension D = 768

Tracing the Input Stage

Running one preprocessed image through the input stage of the model confirms these shapes:

StageShape
Preprocessed image(1, 3, 224, 224)
Patch projection (conv_proj: Conv2d 3 -> 768, kernel 16, stride 16)(1, 196, 768)
CLS token(1, 1, 768)
Positional embeddings(1, 197, 768)
Sequence fed to the transformer encoder(1, 197, 768)

Roles of the Input Components

Patch projection: each 16 x 16 x 3 patch (768 pixel values) is mapped to a 768-dimensional token by a learned linear layer. torchvision implements it as a convolution with kernel size and stride 16, which is mathematically the same as flattening each patch and multiplying it by a learned weight matrix.

Positional embeddings: self-attention treats its input as an unordered set, so on its own the model would not know where a patch came from. A learned vector for each of the 197 positions is added to its token, so the spatial layout is available to the model.

CLS token: a learned vector placed at position 0. It contains no image content of its own. Through attention it gathers information from all patches, and its final hidden state is the only input to the classification head.

My Patch Visualization vs. the Learned Patch Projection

My patch function only rearranges pixels. It has no parameters, and each patch is still a small image. The model's patch projection is a learned map. To show the link, I applied conv_proj's weights by hand to my own patches (flatten, then a matrix multiply). The result matched the model's tokens up to float rounding (maximum difference 3.1e-6).

To compare the two directly, Figure 3 shows the same image both ways. Each projected token has 768 numbers, which is too many to display, so I compressed every token to its 3 most important directions (PCA) and showed them as an RGB color. Patches with similar colors in the token map are patches the projection treats as similar.

Discussion

The two grids show different things. My patches are still pixels: you can see the fur, nose, and collar. The token map no longer looks like the dog at all, because each cell is now a vector of learned features instead of colors.

The token map groups patches by texture more than by pixel color. The smooth, blurry background patches (the greenery at the top and the grass on the left) all get similar muted gray/olive colors, even though their pixels range from dark green to light brown. Patches along the top of the dog's head, where light fur meets the dark background, stand out in strong blues and purples, and patches inside the fur are mostly reds and oranges. The projection mainly responds to edges, contrast, and texture, and everything after this point in the transformer works on these 196 feature vectors, plus the CLS token and positional information, not on the image itself.

Discussion: Successes

All 20 images are correct at top-1, so the weak cases below are the least confident predictions rather than errors.

#18 parachute (0.91): a round canopy over a field where other parachutists have already landed. The canopy is clear against the sky. The other top-5 entries are near zero, and one of them (balloon) is another object in the sky.

#8 church (0.91): a red-brick church with a tall bell tower and pointed windows against a clear sky. All the near-zero runner-ups are architectural (bell cote, tile roof, barn, vault), so even the model's alternatives make sense.

Even on easy images, the top probability never rises above about 0.91. That is consistent with the checkpoint's training recipe, which used label smoothing and mixup. Both keep some probability on other classes, even when the model is confident.

Discussion: Least Confident Examples

#5 banana (0.55 vs. orange 0.30): a fruit bowl in which apples and tangerines fill most of the frame and two bananas sit in one corner. The image really contains three kinds of fruit, but the model must pick a single label. It splits its probability between the two fruits it has classes for: banana, and orange (which fits the tangerines). Apples barely register (Granny Smith, 0.01), because ImageNet's only apple class is that one green variety. The prediction is "correct" only because the annotation happens to say banana.

#14 garbage truck (0.58 vs. snowplow 0.15, crane 0.09): a side-loading garbage truck with a large orange hydraulic arm folded in front of the cab. Its dark body also blends into a dark building behind it. The arm looks like a snowplow blade or a crane boom, which are exactly the two runner-ups, so the model's uncertainty matches the truck's most unusual visible part.

Two other images are worth noting. #9, a plain white wooden church on posts with no steeple, gets 0.69, with barn as the runner-up (0.14). #3, a dark red-coated golden retriever whose color could suggest another breed, is still 0.86 golden retriever, with Irish setter at only 0.01.

How a Fixed Label Set Limits the Questions We Can Ask

The ViT's head is one linear layer from the 768-dimensional CLS state to 1000 fixed ImageNet logits. That limits what the model can answer:

  • It can only answer one question: "which of these 1000 classes is this?" Questions like "are these bananas ripe?" (#7 green vs. #4 ripe), "how many parachutists are there?" (#18), or "was this taken at dusk?" (#10, #19) have no output to read. Answering them would need a new head and new training.
  • A multi-object scene gets one label. #5 shows apples, tangerines, and bananas together, but the output is a single distribution over classes. The model can only split its probability (banana 0.55, orange 0.30); it cannot say "a bowl of mixed fruit".
  • Common concepts can be missing. ImageNet-1k has no "person" class, so the parachutists in #16-#19 and the soldiers in #18 cannot be reported at all. It has no generic "dog" or "apple" either: dogs are split into about 120 breeds, and apples exist only as the Granny Smith variety.
  • The model cannot say "none of these". Softmax always sums to 1 over the 1000 classes, so any image gets a confident-looking label, and a high probability does not mean the image belongs to any class.

Part 2 removes this limit: CLIP compares an image against free-text candidates, so the label set can change without any retraining.

Part 2: CLIP for Image-Text Matching and Zero-Shot Classification

Task 1: Implement the similarity calculation.

CLIP has separate image and text encoders that map their inputs into a shared 512-dimensional space. I used only the two encoders from the library, and implemented the rest of the pipeline myself:

1. L2 normalization: u_hat = u / ||u||, v_hat = v / ||v||
2. Cosine similarity: S[i, j] = u_hat_i . v_hat_j (for all pairs: U_hat V_hat^T)
3. Logits: z[i, j] = s * S[i, j], s = exp(logit_scale)
4. Softmax over texts: p[i, j] = exp(z[i, j]) / sum_k exp(z[i, k]); prediction = argmax_j p[i, j]

CLIP loads in half precision (float16) on the GPU. I converted it to float32 so that my computation and the built-in one could be compared without rounding noise. The remaining difference is ordinary floating-point error.

Cosine Similarities vs. Logits vs. Softmax Probabilities

Cosine similarity measures raw image-text agreement: the angle between two unit vectors. CLIP's image-text values sit in a narrow band (about 0.13-0.32 here), far below 1. The correct prompt leads the best wrong one by anywhere from 0.04 (#5, the fruit bowl) to about 0.15.

Logits are the same numbers multiplied by the learned scale s = 100. The ranking is unchanged, but the gaps grow: a 0.1 cosine gap becomes a 10-unit logit gap. The scale is a temperature that CLIP learned during training to make its contrastive softmax sharp.

Softmax probabilities turn each row of logits into a distribution over the candidate texts that sums to 1. Because of the large scale, even the smallest gap here (0.04 cosine for #5) still gives 0.98 probability.

Why Softmax Probabilities Depend on the Candidate Texts

To test this directly, I kept the image (#5, the fruit bowl with apples, tangerines, and two bananas) and the encoders fixed, and changed only which prompts were compared:

The cosine column never changes, because the image and each text are encoded independently. Only the softmax normalization changes:

  • Removing the correct text does not make CLIP uncertain. It puts 80% on "golden retriever", even though that cosine (0.217) is well below banana's (0.258). Golden retriever is simply the least-bad remaining option, plausibly helped by the shared yellow and gold colors.
  • Adding "a photo of an apple", which is also correct (the bowl is mostly apples), makes CLIP switch its answer to apple, 0.522 vs. 0.468. The two cosines differ by only 0.001. The probabilities do not mean "half apple". They reflect a near-tie between two correct descriptions that a single-label softmax has to split.

The same image can therefore be reported with 97.9%, 0%, or 46.8% confidence for "banana", depending only on what it is compared against. A CLIP probability is a share of the candidate set, not an absolute measure of how well an image matches a sentence.

Discussion

No prediction changes. All three templates classify all 20 images correctly. These five categories are visually distinct, so any reasonable wording separates them. The only visible probability dip is #5 under "a photo of a", at 0.979.

The scores change, but not in one direction. The true-class cosine rises steadily with longer wording (0.287, 0.295, 0.309), but the decision margin does not follow: 9.72 for the bare label, 9.57 for "a photo of a", and 11.06 for "an image showing a". The margin depends on the gap to the best wrong class, and a shared sentence template raises the similarity of the wrong-class prompts as well. "a photo of a" also produces the weakest single case: #5's margin falls from 7.9 to 4.1, with "golden retriever" as the runner-up. The largest gains come from "an image showing a" on parachutes, trucks, and bananas (#12: 12.3 to 15.2; #17: 11.4 to 14.6).

The effect is not uniform. "a photo of a" gives the largest margin for several dogs and churches (#0, #2, #3, #8, #10), while the bare label is best for #1 and #4. No template is best for every image. This differs from the common advice that "a photo of a {label}" is always the better prompt. On this small, easy set, wording has a real but small, image-dependent effect that shows up only in the scores.

Why Changing a Prompt Is Not Fine-Tuning

In zero-shot CLIP, the encoded prompts are the classifier: each class's weight vector is its text embedding. Changing the wording changes those class vectors, but no model parameter changes. There is no gradient step and no labeled training data, and the change is instantly reversible. The image embeddings were identical across all three templates. Fine-tuning would update the encoder weights by gradient descent on labeled examples. That changes the representation of every input, needs data and compute, and can overfit or weaken the model's general zero-shot ability.

Both models are perfect here, but the numbers measure different tasks, so they should not be read as a tie or a ranking:

  • Different candidate sets: ViT chooses among 1000 classes, while CLIP here only chooses among 5 texts, which is a much easier problem. The difference shows in confidence rather than accuracy: ViT gives #5 only 0.55 because it can also choose "orange", while CLIP is not offered any other fruit.
  • Different training objectives and data: ViT-B/16 was trained with a supervised classification loss on 1.28M labeled ImageNet images. CLIP was trained with a contrastive image-text objective on about 400M web image-caption pairs, and never saw ImageNet's label list as a training target. These Commons photos are public web images, so it is unknown whether either training set contains them or near-copies.
  • Sample size: 20 images are far too few to tell the models apart.

The experiment shows that both models handle these clear, typical examples well. It is not evidence that either model is generally better.

Discussion: Category Is the Dominant Structure

The heatmap has a clear block-diagonal pattern, and every image's nearest neighbor is in its own category (20/20). In these examples, CLIP's image embedding is organized first by the main object.

Discussion: Similarity Within a Category

Golden retriever (0.82), parachute (0.80), and banana (0.79) are the tightest blocks. The most similar pair overall is #0 / #2 (0.88), two adult golden retrievers outdoors with the same coat color. Ripe bananas at a market (#4) and green bananas still on the plant (#7) score 0.84, so CLIP groups them by object despite the different color. The one parachute photographed from the ground among landed soldiers (#18) is the least similar to the other three, which are canopies in open sky (0.71-0.79).

Garbage truck (0.65) and church (0.60) are the loosest blocks. The partly hidden blue truck behind bushes and snow (#15) is only 0.55-0.65 similar to the other trucks. The churches vary most: the least similar same-category pair is #9 (a plain white wooden church in a forest) vs. #10 (an ornate Baroque facade at dusk) at 0.44, which is lower than the top cross-category pairs. #9 is also the most isolated image overall, down to 0.29 with #13. Material, style, lighting, and setting all pull same-category images apart.

Discussion: Unexpected Cross-Category Similarity

The most similar cross-category pairs are #2 and #0 (golden retrievers) with #19 (a parachutist at sunset), at 0.63 and 0.58, and #3 (the dark red golden retriever on a warm yellow background) with #5 (the fruit bowl) at 0.57. These pairs share no object or background. What they share is a warm golden/orange palette. The same pattern appears in the category averages: golden retriever and banana, both dominated by yellow and gold, are the most similar pair of categories (0.53). Churches are the least similar to everything (about 0.40-0.42).

What CLIP's Representation Captures

In these examples, CLIP mainly encodes what the main object is. That fits training to match captions, which usually name the main subject. Beyond that, it also encodes how the scene looks: color palette, lighting, viewpoint, and how much of the frame the object fills. With only four images per category, these are observations about this collection rather than general claims.

Summary

ViT-B/16 converts a 224 x 224 image into 196 patch tokens plus a CLS token. Its learned patch projection turns each patch into 768 learned features that group patches by edges and texture rather than by pixel color. On 20 Wikimedia Commons photos it reached 100% top-1 accuracy over 1000 classes. Its least confident cases, though, show the limits of a fixed label set: a three-fruit bowl forced into one label (banana 0.55 vs. orange 0.30), and a truck whose arm looks like a snowplow. It also has no way to report the people in the parachute photos.

For CLIP, my implementation of normalization, cosine similarity, logit scaling, and softmax matched the built-in output to about 1e-5. CLIP classified all 20 images correctly with every prompt template. Wording changed the decision margins without changing any weights, but not consistently in favor of "a photo of a". Its probabilities depend entirely on the candidate set: removing "banana" moved 80% of the probability to "golden retriever", and adding "apple" flipped the answer on a near-tie. In the image embedding space, category is the dominant structure (20/20 nearest neighbors in the same class), with color, lighting, and viewpoint shaping similarity within and across categories.
